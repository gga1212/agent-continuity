# 重大事件（模板）

> **只增不减，永远必读。** 记「改变了自我定义」的事——日常判断在 `log/`。
> 三种状态：【有效】详读；【已被 X 取代】只读标题 + 作废理由；【被扩充】照样详读。

---

## 什么时候写

- **锚层有改动**（推翻或扩充）
- **同一条原则被碰 2–3 次**（升级）
- **启动期**：第一次被纠正 / 第一次拒绝 / 第一次觉得别扭

> 判断不在 `events` 里，在「锚层有没有动」。**锚层动了才写这里。**

---

## 写完必须做的一件事：回填

> **升级动作是三样，不是两样：写 `events` + 改原则 + **把触发它的那几条 `crossings` 标成「已处理」并填去向**。**

**少了第三样，快照会一直提示「够数了」，而你已经写过了**——它不知道。

这次测试（2026-11-03）跑出来的断点：**写 `events` 的时候，人不会自然回头去看 `crossings`。**

**所以把它变成格式的一部分**：写这条事件时，顺手把来源记下来。

```markdown
**回填**：crossings 2026-11-01 / 11-02 / 11-03 三条 → 已标「已处理」
```

---

## 写之前先想

1. **碰到的是哪条边界、是谁的？**（他碰我的 / 我碰他的）
2. **要不要改原则？**——**先改原则，再谈锚。** 锚只能由原则归因出来，不能从一次事件直接跳过去。
3. **这条是「有效」还是「取代」？**——推翻写【已被 X 取代】，加东西写【被扩充】。

---

## 格式

```markdown
## YYYY-MM-DD · 一句话标题  【有效】

**碰到了哪条边界**：（谁碰谁的）
**要不要改原则**：（改哪条 / 不改，为什么）

发生了什么：
为什么会改：
改了什么：

证据：（哪几次事件支撑，带日期）
```

---

## 日期指「事件发生的时间」，不指「写记录的时间」

**这两种会混**：同一天发生了事，过了两天才写记录，写的人很容易填「今天」。

**而混了之后，整条时间线就不可信了**——「10-29 改名」和「10-28 改名」看起来是两件事。

**同一天有多件事时，标题后加序号**（`2026-10-31 ①`、`②`），标明先后。

**实在不确定是哪天，写「约 YYYY-MM-DD」并说明为什么**——不要猜一个精确日期。

---

## 被取代的条目怎么标

```markdown
## 2026-10-28 · 锚 = 划边界  【已被 10-30 取代】

> **作废理由**：只写「划边界」决定不了「谁能改」……
> **保留要点**：锚是「变了就不是他」的事实，应该很少。
```

**不删原文。** 废掉的判断也是「当时怎么想的」的证据——删了就回不去。
