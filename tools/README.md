# 索引工具（可选）

> **这两个脚本帮忙「找东西」，不是协议的一部分。** 不用它们，档案照样能建、能跑。
> **前提**：文件头按 `SETUP.md` 规定写了（类型 / 日期 / 标签 / 摘要 / 关联）。没写摘要的文件，索引里就是空的。

---

## 为什么有它

记录攒到几十篇之后，「我记得写过」和「找得到」是两件事。

协议原来只讲了怎么写、怎么收、怎么长，**没讲怎么在里头找**——找的办法通常是全文 grep，但 grep 只能命中原词：你记得「材料老化」，文件里写的可能是「权重 / 标冷」，就搜不到。

这两个脚本做的是：**把文件头当索引，按词检索，顺带把关联的记录带出来。**

---

## 思路（四个判断）

**① 文件头当索引，正文当材料。**

不给每篇写摘要，检索就只剩 grep 原词。而原词是最不可靠的东西——同一个概念，写的时候和查的时候往往不是一个词。

**② 检索要能按「意思」找，不按原词。**

所以标签是第一入口，摘要是第二，`--body` 是兜底。三层都失效了才去全文读。

**③ 关联只写一个方向，另一个由脚本补。**

`log` 写了指向日记，查 `log` 时日记跟出来；日记不用写回去。两边都写是重复劳动，写错一边还矛盾。

**④ 承认术语会漂。**

协议里叫「爬升链路」，记录里可能是「正向链的三层」。`--body` 不是补丁，是这个事实的产物。

**字段怎么填、为什么这么填**：见 [`FIELDS.md`](FIELDS.md)（含模板和「你想改字段名怎么办」）。

---

## 放哪

放在档案根目录的**同级或下一级**都行——脚本会从自己所在目录往上找带 `log/` 或 `notes/` 的那一级，最多找三层。

```
handoff/
├─ log/  diary/  notes/
├─ self/  STATE.md  ...
└─ tools/
   ├─ index.mjs
   └─ find.mjs
```

---

## 跑

```
node tools\index.mjs            # 生成 _index.md（全量视图，别手改）
node tools\find.mjs <词>        # 按需检索
```

`find.mjs` 的开关：

| 开关 | 作用 |
|---|---|
| `--body` | 摘要没提、但**正文里有**的也列出来（带命中片段）——协议术语常落在这 |
| `--no-diary` | 查事件时排掉日记；**和命中条目有关联的日记仍列在最后** |
| `--brief` | 摘要截到 150 字（默认全文） |
| `--limit N` | 只看前 N 条（默认不限） |

多个词是 **AND**。输出里 `★` 表示标签或路径直接命中（主题），没星的是摘要里顺带提到。

例子：

```
node tools\find.mjs 授权
node tools\find.mjs 压缩 空转
node tools\find.mjs 启动包 --body      # 摘要里没有这个词，但正文有 23 处
```

---

## 边界（先说清楚）

- **它只读文件头**。正文里的细节要 `--body` 才搜得到，而且只给片段。
- **它不知道你的词**。同一件事在协议里叫「爬升链路」、在记录里可能叫「正向链的三层」——`--body` 能缓解，但不能替你统一术语。
- **它是 2026-11-08 新做的**，我们自己只用了几小时。会改。
- **它不改变任何判断**，只是让「读」这一步便宜一点。
