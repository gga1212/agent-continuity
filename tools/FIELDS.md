# 文件头：索引靠的就是这几行

> **先说清楚：协议没规定文件头。** `templates/LOG.md` 规定的是**正文**结构（`# 日期 · 主题` + D1/D2…）。
>
> 下面这七行是我们**额外加的一层**，只为一件事：**让检索能按摘要找到东西，而不是全文 grep 原词**。
>
> **你不需要照抄。** 不加也行——不加的话 `index.mjs` 出空表，`find.mjs` 只剩 `--body` 可用。

---

## 模板

```markdown
---
类型: log
日期: 2026-11-08
状态: 
标签: 索引, 摘要, 工具
摘要: 一两句，写「改了什么」，不写「讲了什么」
关联: 
整理: 未整理
---

# 2026-11-08 · 正文标题照 LOG.md 的模板写
```

---

## 七个字段

| 字段 | 必填 | 干什么 | 不写会怎样 |
|---|---|---|---|
| `类型` | 是 | `log` / `note` / `diary` | 类型列空着，检索不受影响 |
| `日期` | 是 | 排序用 | 退回按文件名前 10 字猜，`2026-11-08` 这种能蒙对 |
| `状态` | 否 | 这件事到哪一步了：已定 / 挂起 / 待验 / 已执行 | 空着 |
| `标签` | 否 | **检索的主要入口** | 只能从摘要和路径里搜 |
| `摘要` | **是** | 索引的全部内容 | 这一篇等于没进索引 |
| `关联` | 否 | 指向相关记录，如 `diary/2026-11-08.md` | 双向带出失效 |
| `整理` | 否 | 抽过原料没有 | 空着 |

**日期和标签最便宜，摘要最值钱。** 只有一行预算的话，写摘要。

---

## 四个设计判断

**① 摘要写「改了什么」，不写「讲了什么」。**

「这篇讲了睡眠整理」在索引里有 89 条，看不出哪条和今天的活有关；「睡前只做不写就会丢的四件，整理留给起床那个」能直接判断要不要展开。

**判据**：读完摘要，你能决定「要不要开这个文件」吗？不能就是写坏了。

**② 索引是生成的，不是手写的。**

索引文件每次都从文件头重算（跑一遍 `index.mjs` 才存在），**不要手改**。会乱的话，说明该改的是文件头。

**③ 关联只写一个方向，另一个由脚本补。**

`log` 写了 `关联: diary/2026-11-08.md`，查 `log` 时日记跟出来；日记那边不用再写回去。反过来也行——**两边写一遍是重复劳动，写错一边还会矛盾**。

**④ `--body` 兜住术语不一致。**

同一件事，协议里叫「爬升链路」、记录里可能叫「正向链的三层」。摘要只收一个词，所以加了 `--body` 去搜正文——**它不是补丁，是承认术语会漂**。

## 想改字段名

两个脚本里搜 `meta['摘要']`、`meta['标签']`、`meta['关联']`、`meta['状态']`，替换成你自己的字段名。**`index.mjs` 和 `find.mjs` 都要改**，否则一个认、一个不认。

字段名用中文、英文都行——`readFront` 是按「冒号前」切分的，冒号中英文都认。
